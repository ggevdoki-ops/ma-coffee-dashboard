# Описание данных

Дашборд работает с тремя типами сущностей от API FusionPOS: **точки**, **смены**, **заказы**. Все деньги — в рублях, время — в MSK (UTC+3).

## Точки

Конфигурация в `points.json` (см. `schema/points.md`). Это владелец всего — на каких хостах логиниться, по какому `point_id` дёргать смены, какой график использовать для сравнения.

В текущем проде 4 точки: **Coffee 42**, **ALT Coffee 1**, **ALT Coffee 2**, **Вместе Лучше**.

## Смены

Смена = интервал от открытия (`open_date`) до закрытия (`close_date`). Если смена ещё идёт — `close_date = null`. По сменам считается:

- **Выручка смены** (`revenue`) — карта + нал, безнал, чаевые (если есть).
- **Статус точки в дашборде** — `open` / `closed` / `no_shift`.
- **Отклонения от графика** — если открытие/закрытие ушли дальше допуска.

## Заказы

Заказы нужны для метрик «чеков», «средний чек», «последний чек». Берём только `status = "paid"`. Если заказов нет — `orders_count = 0`, `avg_check = 0`, `last_order_time = null`.

## Деньги

- Хранятся как `float`, округление до 2 знаков при отдаче.
- Формат на UI: `Intl.NumberFormat('ru-RU')` (пробел как разделитель тысяч, запятая как десятичная). Для `avg_check` на маленьких суммах — без разделителя.
- На карточке знак `₽` живёт рядом с цифрой в одном flex-контейнере с `gap: 2px`, цифра 38px, знак 22px.

## Время

- Все ответы бэкенда — в MSK (`updated_at`, `open_time`, `close_time`).
- Vercel-функция запускается в UTC, поэтому в `api/status.py` есть `MSK_OFFSET = timedelta(hours=3)`. Но реально API v2 уже отдаёт время в MSK, и смещение не применяется к `open_date`/`close_date` (см. `to_msk`).
- Часы на UI (`#clock`) — локальное время браузера, не MSK. Для Москвы совпадает.

## Видимость смены

Три состояния:

| Состояние | Когда |
|-----------|-------|
| `no_shift` | До открытия или после 01:00 следующего дня. |
| `open` | С момента открытия до закрытия. |
| `closed` | После закрытия до 01:00 следующего дня — ещё показываем вчерашнюю. |

Окно запроса к API — 2 дня (`today-1..today`), чтобы в окне до 01:00 достать вчерашнюю закрытую смену.

## Алерты

Только за сегодняшний день. Логика:

- **Позднее открытие**: факт > `schedule.open + 15 мин`.
- **Раннее закрытие**: факт < `schedule.close − 10 мин` (только для закрытых сегодняшних).

Лимит — 8 алертов, сортировка по `delta_min` убыв.

## График работы

`schedule.open` / `schedule.close` — будни.
`schedule.weekend_open` / `schedule.weekend_close` — выходные и даты из `holidays`.

Выходной = `date.weekday() >= 5` (суббота, воскресенье).

## Свод по сети

- `today_total` — сумма `revenue` по точкам за сегодня.
- `open_count` / `total_count` — открыто/всего.
- `orders_count` — сумма чеков по точкам.
- `avg_check` — `today_total / orders_count`.

Если у точки `status = no_shift` и `revenue = 0`, она всё равно участвует в `total_count` — это важно для метрики «открыто точек».

## Что **не** хранится и **не** считается

- Чаевые: API v2 их не отдаёт. Поле `tips` отсутствует, в дашборде всегда 0.
- Удержания (НДФЛ, авансы, штрафы) — отдельный контур расчёта ЗП, не здесь.
- Возвраты и отмены — попадают в `void`-заказы, мы их игнорируем.
- Временные зоны других стран — все точки в Москве.
